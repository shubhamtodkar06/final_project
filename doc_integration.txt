=========================
Frontend Integration Guide
=========================

This document provides the API endpoints and integration details for **authentication**, **resource ingestion**, **chat/chatbot (REST + WebSocket)**, **homework**, **quiz**, **progress/analytics**, **recommendations**, and **reports** for the AI chatbot platform.

All API requests (except registration and login) require authentication using JWT tokens.

## 1️⃣ AUTHENTICATION MODULE (ACCOUNTS APP)

### 1. User Registration
**Endpoint:** `POST /api/auth/register/`
**Headers:** `Content-Type: application/json`

**Example Request:**
```json
{
  "username": "john_doe",
  "first_name": "John",
  "last_name": "Doe",
  "email": "john@example.com",
  "password": "strongpassword123",
  "password2": "strongpassword123"
}
```
**Example Response:**
```json
{
  "id": 1,
  "username": "john_doe",
  "email": "john@example.com",
  "first_name": "John",
  "last_name": "Doe"
}
```
**Notes:** No authentication needed. Creates a new user.

---

### 2. User Login (JWT Auth)
**Endpoint:** `POST /api/auth/login/`
**Headers:** `Content-Type: application/json`

**Example Request:**
```json
{
  "username": "john_doe",
  "password": "strongpassword123"
}
```
**Example Response:**
```json
{
  "refresh": "<refresh_token>",
  "access": "<access_token>",
  "user": {
    "id": 1,
    "username": "john_doe",
    "email": "john@example.com",
    "first_name": "John",
    "last_name": "Doe"
  }
}
```
**Notes:** Use `access` token for API calls. Store `refresh` for renewal.

---

### 3. Get User Profile
**Endpoint:** `GET /api/auth/profile/`
**Headers:** `Authorization: Bearer <access_token>`

**Example Response:**
```json
{
  "id": 1,
  "username": "john_doe",
  "email": "john@example.com",
  "first_name": "John",
  "last_name": "Doe"
}
```
**Notes:** Returns current user info. Requires authentication.

---

### 4. Refresh Access Token
**Endpoint:** `POST /api/auth/token/refresh/`
**Headers:** `Content-Type: application/json`

**Example Request:**
```json
{
  "refresh": "<refresh_token>"
}
```
**Example Response:**
```json
{
  "access": "<new_access_token>"
}
```
**Notes:** Use when access token expires.

---

### 5. Logout / Blacklist Token
**Endpoint:** `POST /api/auth/logout/`
**Headers:** `Content-Type: application/json`, `Authorization: Bearer <access_token>`

**Example Request:**
```json
{
  "refresh": "<refresh_token>"
}
```
**Example Response:**
```json
{
  "message": "Successfully logged out."
}
```
**Notes:** Invalidates refresh token.

## 2️⃣ CHAT MODULE (REST + WebSocket)

### WebSocket & REST Hybrid Chatbot API

This chatbot supports a **hybrid mode**: use the WebSocket (`/ws/chat/`) for real-time, streaming chat and TTS, while all session/message management is handled via REST endpoints (`/api/chatbot/sessions/`). If WebSocket is unavailable (e.g., network issues), you can fall back to the REST endpoints for basic chat.

#### WebSocket Event Types Summary

| Event Type | Description                      | Example Payload (server → client)                       |
|------------|----------------------------------|---------------------------------------------------------|
| `status`   | Typing/status indicator          | `{ "type": "status", "value": "typing", "session_id": "uuid" }` |
| `partial`  | Partial/streamed text response   | `{ "type": "partial", "text": "Supervised...", "session_id": "uuid" }` |
| `final`    | Final full AI response           | `{ "type": "final", "reply": "Full answer...", "session_id": "uuid", "latency_ms": 900 }` |
| `tts`      | TTS audio (base64 WAV)           | `{ "type": "tts", "audio_b64": "<b64>", "content_type": "audio/wav", "session_id": "uuid" }` |
| `error`    | Error message                    | `{ "type": "error", "error": "Something went wrong.", "session_id": "uuid" }` |

**Frontend Tip:** Listen for these event types to update UI. `partial` is optional (sent for long answers), `tts` is only sent if requested.

### Chat Session Management (REST)

**All endpoints require:** `Authorization: Bearer <access_token>`

#### List All Sessions
- **Endpoint:** `GET /api/chatbot/sessions/`
- **Example Response:**
    ```json
    [
      {
        "id": "uuid-string",
        "title": "Session 1",
        "created_at": "2025-06-08T12:34:56Z"
      }
    ]
    ```

#### Create New Session
- **Endpoint:** `POST /api/chatbot/sessions/`
- **Example Request:**
    ```json
    { "title": "New Study Session" }
    ```
- **Example Response:**
    ```json
    {
      "id": "uuid-string",
      "title": "New Study Session",
      "created_at": "2025-06-08T12:34:56Z"
    }
    ```

#### Retrieve or Delete Session
- **Endpoint:** `GET /api/chatbot/sessions/<session_id>/` or `DELETE /api/chatbot/sessions/<session_id>/`
- **Example Response (GET):**
    ```json
    {
      "id": "uuid-string",
      "title": "Session title",
      "created_at": "2025-06-08T12:34:56Z"
    }
    ```
- **Notes:** DELETE returns HTTP 204.

#### Get All Messages in a Session
- **Endpoint:** `GET /api/chatbot/sessions/<session_id>/messages/`
- **Example Response:**
    ```json
    [
      {
        "id": 10,
        "sender": "user",
        "content": "What is supervised learning?",
        "created_at": "2025-06-08T12:35:01Z"
      },
      {
        "id": 11,
        "sender": "assistant",
        "content": "Supervised learning is a machine learning technique...",
        "created_at": "2025-06-08T12:35:05Z"
      }
    ]
    ```

### Real-Time Chatbot (WebSocket)

- **Endpoint:** `ws://<backend-host>/ws/chat/`
- **Query Parameters (optional):** `session_id=<uuid>`, `token=<jwt_access_token>`

#### Example Client → Server Message
```json
{
  "message": "Explain supervised learning.",
  "session_id": "uuid-string",
  "tts": true
}
```

#### Example Server → Client Events

- **Typing Indicator**
    ```json
    {"type": "status", "value": "typing", "session_id": "uuid"}
    ```
- **Partial Response**
    ```json
    {"type": "partial", "text": "Supervised learning is...", "session_id": "uuid"}
    ```
- **Final Response**
    ```json
    {
      "type": "final",
      "reply": "Supervised learning is a method where models are trained using labeled data.",
      "session_id": "uuid",
      "latency_ms": 900
    }
    ```
- **TTS Audio**
    ```json
    {
      "type": "tts",
      "audio_b64": "<base64-wav>",
      "content_type": "audio/wav",
      "session_id": "uuid"
    }
    ```
- **Error**
    ```json
    {"type": "error", "error": "Something went wrong.", "session_id": "uuid"}
    ```

**Hybrid Mode:**  
If WebSocket is not available, you can POST chat messages to a REST endpoint (not shown here) and receive plain responses, but real-time events and TTS will not work.

**Authentication:**  
Pass JWT token via `?token=<access_token>` in the WebSocket URL query string.

**Session Context:**  
Pass `session_id` in your payload to continue an existing chat session, or omit to start a new one.

## 9️⃣ STUDENT NOTES (AI NOTES)

### Generate AI Study Note

    {
      "subject": "Mathematics",

    ```json
    {
      "message": "AI study note generated successfully.",
      "note": {
        "id": 12,
        "subject": "Mathematics",
        "topic": "Fractions",
        "ai_note": "## Fractions Explained\n- A fraction shows parts of a whole.\n- Example: 1/2 means one out of two equal parts.\n**Tip:** Practice by dividing shapes into equal parts.",

        "source_resources": [2, 7]
      }
    }
    ```
**Notes:** The `ai_note` field is markdown-formatted. `source_resources` is a list of related resource IDs.

## GENERAL NOTES
- All timestamps are ISO 8601 strings.
- All secure endpoints require `Authorization: Bearer <access_token>`.
- WebSocket endpoint supports partial/final streaming and TTS.
- Each user can maintain multiple chat sessions.
- When starting a new chat, create a session and use its `session_id`.

## JWT FLOW SUMMARY
1. Register → `/api/auth/register/`
2. Login → `/api/auth/login/` → returns access + refresh
3. Use APIs → send `Authorization: Bearer <access_token>`
4. When expired → `/api/auth/token/refresh/` with refresh token
5. Logout → `/api/auth/logout/` to blacklist token


## 📝 Integration Checklist
1. Register or login to obtain access/refresh tokens via `/api/auth/register/` or `/api/auth/login/`.
2. Store `access_token` (for API) and `refresh_token` (for renewal).
3. For each API call, send `Authorization: Bearer <access_token>`.
4. On 401/403 errors, refresh access token using `/api/auth/token/refresh/`.
5. For chat, create a session (`POST /api/chatbot/sessions/`) and use its `session_id`.
6. For real-time chat, connect WebSocket at `/ws/chat/` with `token` and (optionally) `session_id`. All chat session management is handled via `/api/chatbot/`.
7. Use resource, quiz, homework, progress, recommendations, and report endpoints as needed.
8. Handle all API and WebSocket errors gracefully in the UI.
